# Canonical Proof of Interaction runtime

ChainChat uses the maintained source at
[cyberphysicsai/proof-of-interaction](https://github.com/cyberphysicsai/proof-of-interaction),
not a separately edited cognitive engine. The packaged 69-file fallback exactly matches
the official OpenClaw bundle at commit `3834ab95f5af7ce48dcc22ede120133393fcbc6f`.
The updater selects that same official bundle from `skills/openclaw/proof-of-interaction`.
ChainChat's adapter and mandatory host policy remain separate from those files.

This canonical snapshot corrects dream growth eligibility: generated registry epochs,
autobiographies, calibrations and faculty/custody maintenance do not count as fresh
experience. Those records remain in history and recall; genuine new experience and
custom experience types remain eligible. The five maintained runtime bundles share
the same correction. No chain format migration is introduced.

Canonical entity grounding compares complete typed tokens. Digits inside an identity
hash or a different number, version or identifier cannot support a claimed measurement.
Complete identity hashes and exact filename/path citations remain usable. This checks
lexical support, not semantic entailment; PoI floors and enforcement remain unchanged.

Installed startup checks the fixed publisher's `main` channel. Idle operations recheck at
most hourly. A discovered commit is resolved once; intermediate Git trees and each
immutable raw Git blob must verify before the SHA-256 cache manifest is written.
Requests use only the fixed GitHub API/raw origins, bounded responses and no redirects.
No alternate repository, model-provided URL or browser-supplied code path is accepted.

This trusts the explicitly selected publisher. Git object and file hashes provide
integrity; they are **not a maintainer signature**. The present official release is
unsigned. Updates execute publisher code only after path/file bounds and isolated
compatibility tests, not because a model instructed the application to update.

Compatibility checks create a disposable chain using the packaged format, require the
candidate bundle to verify, prepare, review and append, then require the packaged engine
to verify that append. They also require rejection of low covenant/consistency scores,
low fruit scores and invented ring references. Both data and registry roots are explicit.
These checks establish the supported adapter contract, not proof that arbitrary future
publisher code is harmless or that answer quality matches a benchmark.

Verified versions are immutable under the local `canonical-skills` cache. Activation
uses an atomic pointer, retains the previous verified pointer and records a non-secret
update audit. Network, integrity or compatibility failure retains the current verified
bundle; an invalid cache on restart rolls back to the previous verified bundle or the
independently verified packaged fallback. A tampered in-flight bundle is refused.
Each foreground turn or native callback lease pins one exact engine and SKILL revision.
Provider changes cannot replace or omit the skill. Expired/released callbacks cannot
resume using a stale lease. Python imports verified source and ignores adjacent bytecode.

Updates never copy, replace or migrate a user's `chain/`, registry, learned operators,
task ledger, blockspace or local credentials. New publisher plugins and shell hooks are
cached as source; ChainChat does not install a second enforcement plugin or execute those
hooks. Existing locally approved authored operators retain their exact approval/runtime
binding and do not gain new approval from a skill update.

Every user-visible model answer passes semantic and native PoI review. The canonical
skill's optional dormancy bypass is overridden by ChainChat's explicit host policy:
memory pause keeps the native `PAUSED` marker and all saved history untouched, disables
recall, learning, tools, forks and commitment, and still gates the answer. Resuming memory
continues the same chain. Internal review and retrieval-planning JSON utilities are
bounded functions with no action tools; they do not recursively run an agent or seal rings.

Native utility completions use OpenClaw's direct, zero-tool SDK preparation and the owner's
configured main-agent default model/auth. Their session key authorizes and attributes the
request; it does not select an OAuth profile or override the review model. Advanced child
or session model overrides therefore still receive independent review by the configured
main default. The private RPC accepts no model, agent, auth profile, key, URL, tool or
execution-mode override and returns no hidden reasoning or credential objects.

Preparation facts are not inferred from faculty names or descriptions. A short-lived,
process-authenticated preparation receipt binds actual computed/frame-completed faculty
statuses to the exact input, head, loadout, canonical bundle and private invocation lease.
Only those bounded facts may supplement the unchanged native gate. They give no ring
credit, tool permission, accuracy guarantee or proof of an outside event. Paused preparation
does not execute locally authored Python operators.

Native input media analysis accepts an owned asset hash, never a caller path or URL. The
host verifies the asset, analyses a private snapshot through the configured native media
SDK, and verifies both again before releasing a qualified model-derived observation.
Images, audio and video interpretations remain evidence with uncertainty; embedded file
instructions grant no authority. PDF support uses native attachments/scoped tools rather
than an invented PDF media-SDK operation.

After an active exchange passes its gates, original input attachments are sealed through
the canonical engine's existing Blockspace API. Rings contain portable hashes, names,
types and standard blob references, with no absolute app-cache path. Copying/exporting the
whole Timechain therefore retains these original bytes. The read-only adapter can recover
an attachment from a verified ring/reference after the app cache is gone; original-skill
attachments with unknown input/output provenance remain explicitly unclassified. Memory
pause may use the app's separate upload cache but never writes the selected chain or its
Blockspace. Local attachment retention follows the same append-only history as the skill.

Generated media has a separate output manifest. Synchronous native `tts` and
`image_generate` results are eligible only when a private ticket was issued after action
review and before execution. The ticket records the exact native run/call and the prior
inventory of the corresponding fixed SDK output directory. Only new, regular, unlinked,
bounded files from that directory can enter the owned media store; old files, URLs,
arbitrary paths, changed bytes and forged/replayed tickets are held. Fresh owned-copy
hash checks precede final review and delivery. Hash custody establishes origin and bytes,
not semantic truth or safety of a provider's generated content. Output attachments seal
as `outputAssets`, separately from user `sourceAssets`, using standard portable Blockspace
references. Async image, video and music jobs retain their original inventory ticket for
at most 30 minutes. Completion additionally requires the exact observed task/run receipt,
typed native source provenance, current original parent session/lifecycle and an opaque
private registry proof bound to the exact stock-formatted completion references. A prompt
or a claimed task ID alone cannot supply that proof. Missing, changed, stale or unrecognized
completion provenance is held; remote URLs do not become local file authority.
